# 说话方式注入器实施记录（2026-11-13 17:07 上线）

## 为什么推倒重来

16:56 上线的「恋爱军师」是工具化的：有人求援 → Planner 调 relationship_counsel → 她给建议。
用户当场纠正：**"我要的不是一个军师，而是让她像一个更会说话的人，是让她说这些话，而且是自主地说这些话。"**

含义拆解：
- 她要改变的是**自己的说话质量**（接话、夸人、救场、情绪回应），不是给人当顾问；
- 触发来自**对话处境本身**，不是谁开口求援；
- 「自主」= 不需要人教她何时用，处境到了她自己就用出来了。

## 新架构：说话提示注入（v2）

```
她每次即将开口（replyer 构造完模型请求）
  → 钩子 maisaka.replyer.before_model_request
  → 规则分类当前处境（零 LLM：关键词+强信号+单字冷场特判）
  → 命中且冷却允许：把一张「说话小提示」追加进本次请求的 system item
  → 生成回复时她看到：「【说话小提示·对方在报喜】别只回恭喜…（这是提醒不是台词…）」
```

- **挂载点**：replyer 请求前（**不是**工具调用——没有工具往返、零延迟、不走 Planner）；
- **分类器**：纯规则。14 张卡对应 14 种处境：报喜 / 倾诉受挫 / 吐槽抱怨 / 分享日常 / 冷场单字 / 接梗逗嘴 / 意见不同 / 被求助 / 被夸 / 对方尴尬 / 对方道歉 / 表达关心 / 对方退出 / 调侃分寸；
- **卡片怎么写**：不是知识摘要，是**第二人称的说话提醒**（"别只回恭喜。先接住开心，再追问一个具体细节…例：…"），每张 ≤120 字，带一个可参考的短例句；
- **冷却**（防模板化）：同卡 15 分钟、任意卡间隔 90 秒、每小时最多 10 次。她一小时最多被"提醒"10 次，大部分回复保持原样；
- **幂等**：system item 里有「【说话小提示」标记就不重复注入（重试/多 runner 安全）；
- **成本**：命中时约 100-200 token 输入，无新增模型调用。静默时零成本。

## 按会话类型分频（2026-11-13 17:13，用户拍板）

用户判断：私聊是一对一深聊，说话质量体感最明显，私聊应当用得更积极。实现：

- **会话类型判定双保险**：`chat.receive.after_process` 钩子按 `message_info.group_info` 记录（权威）；session_id 形态（qq_group_*/qq_private_*）兜底。未知会话按默认（克制）处理。会话类型表内存态、上限 200 条。
- **私聊策略**：阈值 **1.0**（单个关键词命中就触发；群聊 2.0 需要两个信号）、同卡冷却 5 分钟、全局间隔 30 秒、每小时上限 30 次。
- **群聊/未知**：维持生产值（2.0 / 15 分钟 / 90 秒 / 10 次）。
- **踩坑**：第一版把私聊阈值设成 1.5 是无效的——分数是整数（弱 1 强 2），1.5 与 2.0 等价，等于没放宽。必须设 1.0 才真正"私聊更容易触发"。
- 日志带 scope：`说话提示注入: card=X score=N scope=private|group|unknown`，冷却跳过同样带 scope。
- 测试：32 项离线测试全过（新增会话类型判定、策略选择、私聊单信号触发、表上限 11 项）。

## v3：拆掉阈值机制，守则进风格层（2026-11-13 17:15，用户拍板）

用户反馈：阈值触发"怪怪的、不够自然"。

分析：①阈值=开关式行为——她有时候被辅导有时候没有，行为不一致；②更根本的是，指令一旦进了生成请求，模型会去"满足指令"，输出反而容易露公式味（照例句说话）。**说话质量的自然来源是稳定的习惯，不是逐条消息的辅导。**

做法：
- 说话提示插件**停用**（toggle 17:15:34，runtime inactive；代码、14 张卡、会话分频逻辑全部保留，随时可开）；
- 守则提炼成一段常驻文本写进 **reply_style**（热重载 17:15:24 生效）：接话先接情绪/细节、夸具体不说空话、难受先顺情绪、关心落实事、留话头、别露"用方法"的痕迹；
- 备份：bot_config.toml.bak_20261113_speech（59866B）。

代价与收益：失去处境特异的针对性（比如"报喜→追问细节"这种只在特定场景出现的引导）；换来行为一致、没有开关式漂移、没有指令味。

如果日后发现某个具体场景（最可能是安慰/倾诉）长期不达标，可单独恢复该场景的卡片——插件配置 toggle 一下即可，或只保留 1-2 张卡的低频注入。

## v4 定稿：三层显形架构（2026-11-13 17:20，用户拍板"所有私聊都开"）

301KB 语料按「能显形的通道」分成三层，各归其位：

| 层 | 内容 | 载体 | 触发 |
|---|---|---|---|
| **习惯层** | 说话的底子（接话/夸人/关怀/话头） | reply_style 常驻文本 | 每条回复 |
| **安全层** | 危险信号处理（问安全/110/120/不劝和） | reply_style 常驻文本 | 出现危机信号时自然适用 |
| **求助层** | 关系深度知识（22 主题摘要） | relationship_counsel 工具 | **仅私聊**、对方明确求教时 |
| 书架 | 其余（历史/书单/哲学/方法论） | knowledge/ 目录 | 不显形，素材库 |

关键实现：`@Tool(..., chat_scope="private")` ——宿主在工具列表层按 `is_group_chat` 过滤（component_registry 948-961 行），群聊里 Planner 根本看不到这个工具，不是靠自律。behavior_style 配了纪律句（【私聊求教】…群里没有这个工具）。插件代码改动通过 **toggle off→on** 热加载生效，不用整机重启（17:20:21 实测）。

至此三次推翻的最终形态：军师模式（错在身份）→ 阈值注入（错在机械）→ **三层定稿（习惯常驻 + 安全兜底 + 私聊求助有深度）**。

## v5 终稿：她是恋爱的主人公，不是军师（2026-11-13 17:28，用户第三次纠偏）

用户："我要的就是说她自己是恋爱的主人公，而不是军师……她不是军师啊。"

这才是最终语义：那批恋爱知识的正确位置是**她自己在感情里的样子**，不是分析别人的工具。被撩时接不接得住、想他时话说不说得具体、不高兴时憋着还是直说、亲密节奏怎么把握——她是当事人，用这些能力过自己的日子。

落地：
- **relationship_counsel 工具彻底撤了**（toggle 17:28:19，连同群聊/私聊一切"顾问"通道）；
- reply_style 新增【谈恋爱的时候】（热重载 17:28:14）：被撩会不好意思但不躲、可以小声反撩；想念说具体的瞬间不说空泛情话；不高兴直说哪件事和想要什么，不阴阳、不冷淡试探；亲密有边界愿意就说不愿意也说；不玩忽冷忽热不拿人刺激谁；
- behavior_style 的【私聊求教】纪律句同步删除。

三层架构最终定型（v5）：
1. **习惯层**（说话的底子）——日常怎么说话
2. **安全层**（有人遇到危险时）——出事时怎么兜
3. **主人公层**（谈恋爱的时候）——她自己感情里怎么爱
4. 书架：其余语料作为素材库，不显形。

至此知识全部以"她是谁"的形态存在，没有任何以"她懂什么、她给谁建议"形态存在的通道。

## v5.1：调情要接球并撩回去（2026-11-13 17:39，用户反馈"还以为会继续调情呢"）

首轮实测：用户发「我中意你/你中意我咩」，她回「像在播报机里念经似的…肚子也饿了」——拆台+岔开，没有接住球。
