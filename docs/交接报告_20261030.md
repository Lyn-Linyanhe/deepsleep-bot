## 四、缓存命中率的真实结构（5.86 已记录，此处补充）

命中率不是线性的，因为它是**算术恒等式**，不是调参结果：
```
命中率 = 1 − 每轮固定未命中 / prompt 总长
```
每轮固定未命中 ≈ 尾部注入 1.5k（时间/记忆/画像/wait 提醒，永远全新）+ 本轮新增历史。

**控制间隔后的干净数据（只取 <60s 连发，1588 条）：**
| prompt 区间 | 命中率 | 元/1k token |
|---|---|---|
| 6k-8k | 56.6% | 0.00025 |
| 10k-12k | 61.8% | 0.00022 |
| 14k-16k | 68.0% | 0.00024 |

**间隔才是真正的驱动变量**（不是长度）：
| 间隔 | 命中率 |
|---|---|
| <60s | 60.9% |
| 15-30min | 41.8% |
| >1h | **20.9%** |

→ 真正值得优化的是**冷启动**（今日 179 条，命中率仅 21-41%），不是 cap。

## 六、踩过的坑 / 环境注意

- **「双实例」是假象**：uv venv 用蹦床启动器，`.venv python` + `系统 Python` 是同一进程两层。判断实例看端口，别数进程。
- `cmd /c xxx.bat` 从 Git Bash 调用会静默失效；用 WMI `Invoke-CimMethod Win32_Process Create`。
- `Get-NetTCPConnection` 在本机 WMI 上下文中会**无限挂死**；`netstat -p TCP` 输出为空不能用，只能 `netstat -ano`。
- 插件**热重载只换配置不换代码**——改 `plugin.py` 必须重启。
- 后台跑长任务（如 payload 扫描）容易卡住，尽量缩小扫描范围。
