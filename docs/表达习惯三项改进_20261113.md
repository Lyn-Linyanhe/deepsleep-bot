# 表达习惯三项改进：语境加权、反馈闭环、黑话毕业线（2026-11-13）

## 动机（用户点名修的三件事）
1. 表达选择"盲抽"（快模式纯加权随机，不看语境）；
2. 没有反馈闭环（被无视/被怼不影响学到的表达）；
3. 黑话结构性问题（2432 候选积压、count≥100 毕业线不可达、无人工审核）。

约束：全部确定性实现，零新增 LLM 调用（精模式 selector 是串行 LLM 往返，会增加每条回复延迟，不启用）。

## 实现
### ① 语境加权抽样（maisaka_expression_selector.py）
- 快模式候选池构建前新增分支：用 `_build_expression_query_text`（reply_reference/expression_intent/planner 推理）作查询，
  对全部候选算「情景+风格文本 vs 查询」的字级 bigram 包含系数；相关度 top10 中系数 ≥0.12 的候选
  加权抽最多 3 条置顶插入，其余名额仍走原有 5 高频+5 随机加权抽样，合并去重上限 10。
- 查询无参考或候选<10 时退化为原逻辑；向量路径未动。
### ② 反馈闭环（新文件 src/learners/expression_feedback.py + 两处接线）
- 发出侧（reply.py 发送成功后）：记录 她 sent_message_id → 本次 selected_expression_ids
  到 data/expression_feedback/feedback.sqlite3（TTL 3 天）。
- 入站侧（memory_flow_service.on_incoming_message 增加观察任务）：
  * 有人 reply 引用她的消息且文本命中保守负面词表（闭嘴/好吵/烦…17 词）→ 那批表达 count-1，
    下限 1 不删行；
  * QQ 表情回应通知（适配器折叠为文本 `[事件-群消息表情回应]…对消息(ID:x)…`）命中她的消息
    → count+1，上限 500；中性引用不动。
- count 变更后按 use_vector_expression 开关同步表达向量索引（派生数据，失败仅记日志）；
  全部效果走日志「表达反馈生效」。
### ③ 黑话毕业线（jargon_miner.py）
- is_complete 阈值 100→20（全库历史最高 count=95，100 实际不可达；20 次重复出现的词义已稳定）。
  定稿后不再重复推断，learner 容量让给积压候选。
- 未做：候选积压排序消化（推断由词再次出现自然驱动，强推会烧 LLM）与人工审核通道（表达库有 checked 字段、黑话库没有）——如实遗留。
