# 记忆优化与本地向量链路恢复（2026-11-17）

本次更新相对前一提交 `ca73c41`，代码仍以相对 MaiBot v1.3.18 的累计 `0001` 补丁分发。不要把新 `0001` 再叠加到旧 `0001` 上。

## 修复与改动

- **回环服务直连。** OpenAI 兼容客户端对 `localhost`、IPv4/IPv6 loopback 不使用环境代理；外部及局域网端点保留既有代理策略。修复本地 embedding 服务可用、但 MaiBot 请求被送到不可用代理后持续降级的问题。没有改全局代理，也没有新增重复的定时恢复机制。
- **完整条目预算。** 安全说明、换行、编号和记忆正文一起计算预算，先给可容纳的当前会话候选保留位置，再补其他条目。放不下则跳过，不再切成半句，也不会在900字符预算后再追加省略号而超限。
- **实际采用后计数。** 启发式搜索可以延后访问记账，返回绑定真实会话的短期、一次性候选回执。选择完成后只确认实际呈现的段落和关系；未知ID、跨会话、过期和重放拒绝。确认前复验存在性、删除、失效与范围，剔除项不会进入提示词。普通记忆查询默认行为不变。
- **减少失败重复工作。** 消息计数及历史读取放到工作线程，空印象或异常增加短退避；缓存命中不重复计数。

该回执是内部进程中的采用确认机制，不是API访问凭据，不向聊天工具暴露。

## 验证

- `tests/test_memory_optimization.py`：8项隔离测试，覆盖完整预算、极小预算、最终集合一致、参数透传、单次采用与复验。
- `tests/test_loopback_proxy_routing.py`：用真实客户端构造方法、本地假HTTP服务器及不可用代理验证路由；不调用真实模型、不连接公网。
- `tests/test_audit_repairs.py`：原19项公开版审计回归继续通过。
- 7个修改文件编译通过，部署时一次重启MaiBot；QQ、embedding和模型网关没有重启。
- 部署后MaiBot强制自检返回1024维、约127毫秒，`embedding_degraded=false`、`retrieval_mode=hybrid`、`vector_rebuild_required=false`；后续定时状态仍正常。未删除历史记忆、未重建索引。

以上验证逻辑和调用链，不代表真实聊天记忆准确率已有量化提升。完整上游pytest套件未运行。

## 已知边界

- 当前会话保底仍只能选已进入候选的记忆，无法救回没有进入全局前20条的本会话记录。
- 计数表示完整记忆进入启发式内部参考，不表示模型最终在回复中引用或使用了该事实。
- 缓存仍保存字符串，复用时没有逐条重新检查权限或可见性；画像、人物事实和图片关联的全链来源隔离仍需单独设计。
- 图片向量模型、画像刷新周期、检索融合权重、自动纠错开关本次没有调整。
- 过去用目标记忆前120字回查自身的高命中率，只是原文回查基准，不能当作真实聊天问答准确率。
- A_Memorix内部变更是本地接入兼容补丁；升级时应同步或移植到上游MaiBot_branch，并复核接口。

前一批审计文档记录的是当时状态；其中“SDK返回后继续筛选但仍提前计数”的条目由本更新中的采用确认机制替代。
